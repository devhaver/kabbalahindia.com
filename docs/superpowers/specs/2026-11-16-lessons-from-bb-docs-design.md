# Daily lessons on kabbalahindia.com — design

Status: draft, awaiting owner approval. Build is sequenced **after** the site
redesign (see Constraints).

## Intent

The Daily Lessons site (`BB-Docs/BB-Docs.github.io`, live at
<https://bb-docs.github.io>) keeps existing and keeps being published exactly as
it is today. kabbalahindia.com reads from it and shows the lesson **texts** on
its own pages, so a visitor can browse and read lessons without leaving
kabbalahindia.com.

## Goals

- All published lessons are listed and readable on kabbalahindia.com.
- A lesson published on the lessons site appears on kabbalahindia.com within
  minutes, with no extra step in the daily publishing routine.
- Lesson text is identical to the original.

## Non-goals

- Audio narration. Text only; no player, no audio badge.
- Search, Telegram/WhatsApp/RSS subscribe page, or light/dark toggle on
  kabbalahindia.com.
- Moving, replacing, or redirecting the lessons site.
- A lessons strip on the landing page. The landing page only gains a "Lessons"
  link in the header.

## Anti-goals

- The landing page must not get slower or less focused on signups.
- A lessons-site outage must never break kabbalahindia.com pages other than the
  lessons pages themselves.
- No second copy of lesson content committed to this repo.

## Constraints

- kabbalahindia.com is Nuxt 4 on Cloudflare Pages; every route renders through
  the Worker (`server/middleware/canonical.ts` depends on that).
- The lessons site is Jekyll on GitHub Pages with no custom plugins, so it can
  only emit one file per template. Its RSS feed carries the newest 10 lessons
  only and weighs ~174 KB because it includes full bodies.
- GitHub Pages serves with `access-control-allow-origin: *` and
  `cache-control: max-age=600`.
- No new dependencies in this repo.
- The site's visual design is about to be reworked. Lessons pages are built on
  the new design tokens, so this work starts once the redesign has landed.

## Approaches considered

1. **Slim index + rendered-page extraction (chosen).** The lessons site emits a
   small `lessons.json` index. kabbalahindia.com reads the index for the list,
   and for a single lesson fetches the already-rendered page from the lessons
   site and extracts the body. Text is byte-identical to the original, no new
   dependency, works for every lesson.
2. **RSS feed only.** Nothing to add on the lessons site, but only the newest
   10 lessons are available and each request pulls 174 KB. Rejected: the
   archive is 178 lessons and growing.
3. **Raw Markdown from GitHub, rendered in Nuxt.** Fetch `_posts/*.md` from
   `raw.githubusercontent.com` and convert. Rejected: adds a Markdown library,
   and kramdown-vs-other rendering differences would make the text drift from
   the original.

## Design

### Lessons site (`BB-Docs/BB-Docs.github.io`)

- New `lessons.json` at the site root, generated by Liquid the same way
  `search.json` is, one entry per post, newest first:
  `{ "title", "subtitle", "date" (YYYY-MM-DD), "path" }` where `path` is the
  post URL, e.g. `/lessons/2026/11/16/what-it-means-…/`. No body. ~40 KB for
  178 lessons.
- `_layouts/lesson.html`: wrap `{{ content }}` in a pair of HTML comment
  markers (`<!-- lesson-body:start -->` / `<!-- lesson-body:end -->`) so the
  body can be cut out reliably. No visible change.

### kabbalahindia.com

- `server/utils/lessons.ts`
  - `fetchLessonIndex()` — GET `lessons.json`, validate with valibot, return
    typed entries.
  - `fetchLessonBody(path)` — GET the rendered lesson page, return the HTML
    between the markers. Rejects any `path` not present in the index, so the
    route cannot be used to proxy arbitrary URLs.
  - `sanitizeLessonHtml(html)` — allow-list of the tags kramdown emits
    (headings, p, ul/ol/li, blockquote, strong/em, a, hr, table family, code);
    everything else, and all attributes except `href` on links, is dropped.
    Relative links and image sources are rewritten to absolute lessons-site
    URLs.
- `server/api/lessons/index.get.ts` and `server/api/lessons/[...path].get.ts`,
  both cached ~10 minutes (`defineCachedEventHandler`, stale-while-revalidate).
  The existing `/api/**` `no-store` route rule is narrowed so it does not
  defeat this cache.
- `app/pages/lessons/index.vue` — all lessons, newest first, grouped by month:
  date, title, subtitle.
- `app/pages/lessons/[...path].vue` — title, subtitle, date, body, previous /
  next links (derived from the index), "← All lessons".
- Lesson URLs mirror the lessons site: `/lessons/YYYY/MM/DD/<slug>/`.
- `SiteHeader.vue` gains a "Lessons" link.
- SEO: each lesson page sets `<link rel="canonical">` to the lessons-site
  original; the list page is canonical on kabbalahindia.com.
- Failure: if the lessons site is unreachable or the markers are missing, the
  lessons pages render a "Lessons are unavailable right now" state with a link
  to the lessons site; unknown paths return 404.
- Runtime config: `NUXT_PUBLIC_LESSONS_BASE_URL`, default
  `https://bb-docs.github.io`, documented in `.env.example`.
- Date formatting uses one shared `Intl.DateTimeFormat` instance.

### Tests (Vitest)

- Index validation: good payload, malformed payload.
- Body extraction: markers present, markers missing.
- Sanitizer: script/style/event-handler stripping, relative-link rewriting.
- Path guard: path not in the index is rejected.

## Calls made by the author (not yet confirmed by the owner)

- Canonical URL points at the lessons-site original.
- Header link only; no landing-page strip.
- 10-minute cache.
- Lessons grouped by month on the list page.

## Left to the builder

- Exact cache keys and stale-while-revalidate windows.
- Typography and spacing of the lessons pages, within the redesigned tokens.
- Whether prev/next comes from the list endpoint or a combined lesson payload.
